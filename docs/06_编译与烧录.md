# 编译与烧录

## Keil 00–02

打开实验根目录对应 `.uvproj`，检查 STC89C52RC 目标、11.0592 MHz/12T 的实际板卡设置及 `STC89C5xRC.H` 可用性，Build 后在 `Objects/` 查目标 `.hex`。`.uvproj` 引用同目录 `main.c`、`STARTUP.A51`，所以这三个文件未搬到 `src/`。构建输出本地保留但被 Git 忽略。

## VS Code + EIDE 03–19

以**单个实验**的 `.code-workspace` 或工程文件夹打开；EIDE 选择 `Keil_C51`、`Release` 并构建。`03` 的配置是旧版 `.eide/eide.yml`，04–19 是 `.eide/eide.json`；如果当前 EIDE 不兼容旧版格式，先核对 EIDE 迁移提示，勿直接修改课程源码。编译前核对 Keil 安装位置与配置中的 STC 头文件路径（历史值 `c:/Program Files/Keil_v5/C51/INC/STC`）。输出在各工程的 `build/Release/`，不提交 `.hex`/对象文件。

## 烧录前检查

1. 确认编译结束且存在**本次**生成的 HEX；不能用其他实验的旧文件代替。
2. 接好 USB 串口，设备管理器确认 CH340K 对应当前 COM 号；COM3/COM5 只是既往例子。
3. STC-ISP：选择 STC89C52RC、实际串口和匹配的时钟/模式，导入 HEX，按工具提示进行冷启动/重新上电下载。
4. EIDE 自定义上传：工程配置调用 `python ../../tools/stcflash.py -p ${port} "${hexFile}"`；这是共享的 GPL 脚本。先在同一 Python 环境确认 `import serial` 可用，且 EIDE 解析了正确的 `${port}`/`${hexFile}`。不建议同时打开占用串口的监视器。
5. 下载后断开或切换串口监视工具，再按实验 README 验证现象并记录实际端口、HEX、硬件版本与观察结果。

仓库建立时没有执行烧录，也没有把历史构建日志视为新环境通过的证据。实际使用串口/电源前请先核对实物接线。[真实故障记录](07_调试记录.md)。
