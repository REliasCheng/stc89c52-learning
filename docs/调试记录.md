## 之前实际碰到的环境问题

| 现象 | 确认过的定位方向 |
| --- | --- |
| Python 提示没有 `serial` | 安装包名是 `pyserial`，并且必须装到 EIDE 真正调用的解释器中。 |
| CH340K 的 COM 口变化 | 先查看设备管理器和硬件 ID，再选端口；历史 COM3/COM5 不能硬编码。 |
| 找不到 HEX / flash 不起作用 | 先查本次 Build 和 `build/Release/`，再查 `.vscode/tasks.json` → EIDE → 自定义上传的调用链。 |

以上是开发环境排障，不等于当前 12 个主题已逐一上板。

## 只读代码时发现，尚未判定为板上故障

- 数码管动态工程的 `u16` 是 `unsigned char`，与延时参数名称不符。
- UART 单字节工程启用了 `ET1`，但未见 Timer1 ISR；收到 `0x00` 也无法由其非零缓冲标志表达。
- UART 多字节工程对 16 字节接收缓冲无上界保护，主程序还要给字符串终止符留位置。
- DS18B20 工程发出转换命令后立即读取，没有明确等待当前转换完成。
- DS1302 综合工程每次上电写入示例时间；`WEEK_NAME[day_of_week - 1]` 需要检查返回范围。
- 外部中断工程在 ISR 内延时 10 ms 消抖；定时器初版的 ISR 名为 `Dir_Timer0_Handler`，与其他 `Dri_` 命名不同。

课程源码保持原样。以后修复时，应在自己的实现或明确标注的修订提交里写：原始版本如何表现、改了哪里、怎样复测。现在不把“推测有问题”写成“已解决”。
