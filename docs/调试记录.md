# 调试记录：已遇到与仅发现疑点分开

[首页](../README.md) · [学习记录](学习记录.md)

## 之前实际碰到的环境问题

| 遇到的现象 | 原因定位 | 处理方式与收获 |
| --- | --- | --- |
| EIDE 上传时 Python 提示没有 `serial` | `serial` 来自 `pyserial` 包；系统里有多个 Python 时，装在别的解释器上对当前上传任务无效。 | 找到 EIDE 实际调用的解释器，在同一解释器执行 `-m pip install pyserial` 并验证 `import serial`。我把“工具能打开”和“上传环境可用”分开检查。 |
| CH340K 端口出现 COM3/COM5 变化 | 串口号随连接和系统分配变化，不是板卡永久属性。 | 先核对设备管理器中的当前端口和硬件 ID，再选上传端口；不按旧日志盲改配置。 |
| 找不到 HEX，或点 `flash` 没有得到预期结果 | `.vscode/tasks.json` 只委派 EIDE 上传；若本次 Build 未产出 HEX 或路径不符，上传环节没有正确输入。 | 先查构建结果与工程的 `build/Release/`，再沿 EIDE 配置的 `${hexFile}` 和自定义上传脚本排查。我把构建故障与串口故障分层处理。 |

以上是确实遇到过的开发环境排障，不应被误记为每个主题的独立硬件测试报告；它也不否定既有课程实践。

## 只读代码时发现，尚未判定为板上故障

- 数码管动态工程的 `u16` 是 `unsigned char`，与延时参数名称不符。
- UART 单字节工程启用了 `ET1`，但未见 Timer1 ISR；收到 `0x00` 也无法由其非零缓冲标志表达。
- UART 多字节工程对 16 字节接收缓冲无上界保护，主程序还要给字符串终止符留位置。
- DS18B20 工程发出转换命令后立即读取，没有明确等待当前转换完成。
- DS1302 综合工程每次上电写入示例时间；`WEEK_NAME[day_of_week - 1]` 需要检查返回范围。
- 外部中断工程在 ISR 内延时 10 ms 消抖；定时器初版的 ISR 名为 `Dir_Timer0_Handler`，与其他 `Dri_` 命名不同。

课程源码保持原样。以后修复时，应在自己的实现或明确标注的修订提交里写：原始版本如何表现、改了哪里、怎样复测。现在不把“推测有问题”写成“已解决”。
