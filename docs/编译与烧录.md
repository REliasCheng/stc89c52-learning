# 把一个实验跑起来

[首页](../README.md) · [环境](开发环境.md) · [排错](常见问题.md)

以 [`projects/01_LED/src/course/00-点亮LED`](../projects/01_LED/src/course/00-点亮LED/) 为第一次尝试，**不要**从仓库根目录找统一的 Build 按钮。

1. Keil 工程（00–02）：打开工程根目录内的 `.uvproj`；确认芯片/头文件与本机 Keil C51 可用，Build 后查看该工程 `Objects/` 里的新 HEX。
2. EIDE 工程（03–19）：在 VS Code 打开该工程自己的 `.code-workspace` 或工程目录，选择 `Keil_C51` 与 `Release`，先 Build；HEX 通常在该工程的 `build/Release/`。03 的 `eide.yml` 是旧版格式，若当前 EIDE 不兼容，应先按其提示迁移**个人工作副本**。
3. 每次下载前检查 HEX 的路径和生成时间；连接板卡与 CH340K，确认设备管理器里当前 COM 号、供电、芯片型号和实际板卡晶振。不要把旧的 COM3/COM5 当作本机常量。
4. 可用 STC-ISP 选择 STC89C52RC、当前串口和对应 HEX，按下载工具提示重新上电；也可在 EIDE 使用自定义上传，工程会调用 `python ../../../../../tools/stcflash.py -p ${port} "${hexFile}"`。后者需要当前 Python 能 `import serial`（包名 `pyserial`）。
5. 下载后再打开串口监视器或观察 LED/显示器，记录**实际**现象与失败信息。Build 成功、HEX 存在、串口下载成功、板上行为正确是四件不同的事。

Keil 的 `Objects/`、`Listings/` 和 EIDE 的 `build/` 都被忽略；它们会在本机生成，但不随仓库下载。若未来发布可复现的固件，单独把对应 HEX 放到 GitHub Release，并注明源提交、工具链和目标板版本。
