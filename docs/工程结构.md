# 读工程时从哪里下手

[首页](../README.md) · [实验目录](../projects/README.md)

先进入一个主题，再选择 `src/course/` 下的完整工程。课程在不同阶段复制并调整同名模块，因此这些文件按工程保存，不合并成单一驱动库。

```text
projects/08_UART/
├─ README.md              主题入口与工程导航
├─ notes/README.md        接口、调用关系和版本差异
└─ src/course/
   ├─ 14-串口-单字节命令/  独立 EIDE 工程
   └─ 15-串口-多字节命令/  另一个独立 EIDE 工程
```

00–02 的 `main.c`、`STARTUP.A51`、`.uvproj` 保留在各工程根目录以维护 Keil 相对路径。后面的 `src/main.c` 是应用流程；`Com/` 放公共类型/延时，`Dri/` 放 Timer0、UART、IIC、1-Wire 等底层，`Int/` 放数码管、按键、EEPROM、OLED 等器件接口。比如 EEPROM 的阅读顺序是 `main → Int_EEPROM → Dri_IIC`，而点阵显示另走 `Int_LEDMatrix → Dri_Timer0`。

## 代码结构的变化

- **00–04：直接控制引脚。** LED 工程在 `main.c` 操作 P0；数码管静态和动态工程也在入口里完成 P1 位选、P0 段码与扫描。这个阶段最容易把“显示数字”和“驱动显示器”写在一起。
- **05–09：先把器件行为抽出。** `Int_DigitalTube` 接管显示，`Int_Key` / `Int_KeyMatrix` 接管按键，`Int_Buzzer` 接管声音。`main()` 开始像应用流程：读一个事件，再决定输出什么。INT0 工程则表明事件也可以从中断进入。
- **10–15：时间与通信下沉到驱动。** Timer0 从 ISR 直接翻灯发展为回调注册；点阵把刷新放到回调，UART 多字节工程用它识别帧间空闲。这里同一计时资源服务了不同应用，开始需要关注中断中的执行时间与共享状态。
- **16–19：器件组合。** `Dri_IIC`、`Dri_1Wire` 提供时序，`Int_EEPROM`、`Int_OLED`、`Int_DS18B20`、`Int_DS1302` 负责设备语义；`main()` 把存储、显示、温度和时钟接成具体流程。分析故障时可以沿层次定位，而不是只在入口里找问题。

同名驱动在不同工程中并不相同。例如 `Dri_IIC_SendByte` 在 [EEPROM 版](../projects/09_I2C与AT24C02/src/course/16-EEPROM/src/Dri/Dri_IIC.c)用掩码取位，在 [OLED 版](../projects/10_OLED/src/course/17-OLED/src/Dri/Dri_IIC.c)用 `bdata`/`sbit` 取最高位；`Com_Util.h` 的 `u16` 在早期工程定义为 `unsigned char`，后期工程才改为 `unsigned int`。阅读或复用接口时需要先确认所在工程和对应版本。

原工程各带一份相同的 GPL `stcflash.py`，仓库在 [`tools/`](../tools/README.md) 保留一份；EIDE 配置中的上传脚本相对路径相应改为 `../../../../../tools/stcflash.py`。`templates/eide-c51/` 保存课程使用的 EIDE C51 模板。
