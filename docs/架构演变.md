# 从端口操作到多外设协作

[首页](../README.md) · [工程结构](工程结构.md) · [实验目录](../projects/README.md)

这些工程中的 main.c 逐渐从直接操作引脚转为组织输入、处理和输出。源码可按四个阶段阅读，早期点灯工程保持直接控制，后期工程再引入接口和驱动分层。

## 1. main.c 直接控制端口

[LED 三个工程](../projects/01_LED/)直接写 P0，程序行为几乎都在 main.c 中。[数码管静态工程](../projects/02_数码管/src/course/03-数码管-静态显示/)加入 P1 位选和 P0 段码：一个端口值不再足以解释显示结果，还要追 74HC138 的选择线、74HC245 的段线与 P3.6 使能。

这个阶段的优势是调用链短，适合确认端口电平与板上效果的关系；当扫描、输入和显示内容同时出现时，直接控制会让应用流程和硬件时序交织。

## 2. 器件行为形成接口

[数码管模块化工程](../projects/02_数码管/src/course/05-数码管-模块化编程/)引入 Int_DigitalTube；[独立键与矩阵键](../projects/03_按键/)将消抖、行列定位放进键盘接口；[蜂鸣器](../projects/04_蜂鸣器/)把 P4.6 的翻转包装为声音动作。main 开始表达“读到什么键，触发什么输出”，不用重复描述每个电平细节。

Int 在这些工程里代表器件/功能接口，不等于所有硬件都会有一层同名目录。不同工程要按实际文件判断。

## 3. 时间资源独立

[Timer0 初版](../projects/06_定时器/src/course/10-定时器/)在 ISR 中直接计数翻灯；[封装版](../projects/06_定时器/src/course/11-定时器封装/)让应用注册回调。之后，[点阵](../projects/07_点阵/)通过定时回调持续刷新，主循环只负责静态图案或较慢的滚动；[UART 多字节工程](../projects/08_UART/src/course/15-串口-多字节命令/)用空闲节拍判断命令结束。

这一步把时间基准与应用动作分开，但也带来资源管理问题：中断内任务耗时、回调槽容量、共享状态和主循环阻塞都需要在组合应用中重新评估。

## 4. 底层时序、器件语义和应用组合

[EEPROM 工程](../projects/09_I2C与AT24C02/)沿 main → Int_EEPROM → Dri_IIC 完成图案读写，再交给点阵显示。[OLED](../projects/10_OLED/)共享 P1.6/P1.7 这组总线线脚，但器件命令与显示字模放在自己的 Int_OLED 中。[DS18B20](../projects/11_DS18B20/)增加 Dri_1Wire；[DS1302](../projects/12_DS1302/)把 RTC、温度和 OLED 接在同一个 main 流程。

一个功能可沿三条线追踪：**板级信号路径**说明数据从哪根引脚到哪个器件，**函数调用链**说明各层职责，**时间线**说明转换、刷新与中断何时发生。三条线共同解释板端行为。

## 版本边界

同名文件在不同实验中可能实现不同。EEPROM 版 I²C 逐位掩码发送，OLED 版使用位变量和移位；早期数码管工程的 u16 类型定义也与后期不同。[工程结构](工程结构.md)保留了这些对应关系。独立实现放在对应主题的 `practice/` 中，与历史快照对照。
