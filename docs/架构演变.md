# 从端口操作到多外设协作

> Historical Reference：本页描述历史课程工程中的架构观察；其源码不在当前公开仓库中，不是当前可构建项目的结构图。当前原创实现见[终端项目](../projects/13_环境与时钟信息终端/README.md)。

[首页](../README.md) · [工程结构](工程结构.md) · 实验目录

历史工程中的 main.c 逐渐从直接操作引脚转为组织输入、处理和输出。以下四个阶段是分析记录，非当前仓库内的源码导航。

## 1. main.c 直接控制端口

LED 三个工程直接写 P0，程序行为几乎都在 main.c 中。数码管静态工程加入 P1 位选和 P0 段码：一个端口值不再足以解释显示结果，还要追 74HC138 的选择线、74HC245 的段线与 P3.6 使能。

这个阶段的优势是调用链短，适合确认端口电平与板上效果的关系；当扫描、输入和显示内容同时出现时，直接控制会让应用流程和硬件时序交织。

## 2. 器件行为形成接口

数码管模块化工程引入 Int_DigitalTube；独立键与矩阵键将消抖、行列定位放进键盘接口；蜂鸣器把 P4.6 的翻转包装为声音动作。main 开始表达“读到什么键，触发什么输出”，不用重复描述每个电平细节。

Int 在这些工程里代表器件/功能接口，不等于所有硬件都会有一层同名目录。不同工程要按实际文件判断。

## 3. 时间资源独立

Timer0 初版在 ISR 中直接计数翻灯；封装版让应用注册回调。之后，点阵通过定时回调持续刷新，主循环只负责静态图案或较慢的滚动；UART 多字节工程用空闲节拍判断命令结束。

这一步把时间基准与应用动作分开，但也带来资源管理问题：中断内任务耗时、回调槽容量、共享状态和主循环阻塞都需要在组合应用中重新评估。

## 4. 底层时序、器件语义和应用组合

EEPROM 工程沿 main → Int_EEPROM → Dri_IIC 完成图案读写，再交给点阵显示。OLED共享 P1.6/P1.7 这组总线线脚，但器件命令与显示字模放在自己的 Int_OLED 中。DS18B20增加 Dri_1Wire；DS1302把 RTC、温度和 OLED 接在同一个 main 流程。

一个功能可沿三条线追踪：**板级信号路径**说明数据从哪根引脚到哪个器件，**函数调用链**说明各层职责，**时间线**说明转换、刷新与中断何时发生。三条线共同解释板端行为。
