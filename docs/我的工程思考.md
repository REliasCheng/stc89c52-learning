# 硬件资源与数据流

[首页](../README.md) · [工程结构](工程结构.md) · [硬件引脚](../hardware/引脚映射.md) · [调试记录](调试记录.md)

这份说明沿教学板 V1.0 图纸和工程调用关系，记录共享端口、定时资源、总线分层与多外设组合时的检查顺序。

## 一根 P0，不止一个外设

最早的[点灯代码](../projects/01_LED/src/course/00-点亮LED/main.c)直接拉低 P0.0。到了[数码管静态显示](../projects/02_数码管/src/course/03-数码管-静态显示/src/main.c)，P0 变成段码数据，P1.3–P1.5 通过 74HC138 选位；到[点阵](../projects/07_点阵/src/course/12-点阵LED/src/Int/Int_LEDMatrix.c)，P0 又参与一行像素的输出。P3.4/P3.5/P3.6 的使能决定当前谁在使用这组线。

`P0 = ...` 只描述了数据，不能说明当前选中的外设。定位“灯没亮”或“显示错位”时，应同时检查**数据线 + 选通线 + 外设**，确认段码和选通信号属于同一条路径。[板级接线依据](../hardware/引脚映射.md)

## 定时器提供节拍，应用决定动作

[Timer0 初版](../projects/06_定时器/src/course/10-定时器/src/Dri/Dri_Timer0.c)在 ISR 内计数并直接翻 LED；[封装版](../projects/06_定时器/src/course/11-定时器封装/src/Dri/Dri_Timer0.c)维护回调表。此后点阵把扫描函数注册进去，[UART 多字节工程](../projects/08_UART/src/course/15-串口-多字节命令/src/Dri/Dri_UART.c)也注册空闲计数函数。它们复用同一类时间基准，却执行不同的应用任务。

驱动负责定时器重装和回调分发，应用负责显示刷新或帧结束判断。中断回调会直接影响响应时间，因此不适合放入长时间阻塞操作；[INT0 中的 10 ms 延时](../projects/05_外部中断/src/course/09-外部中断/src/main.c)提供了一个可直接检查的取舍例子。

## 总线动作与器件语义分层

在[EEPROM 工程](../projects/09_I2C与AT24C02/src/course/16-EEPROM/src/main.c)，`main` 操作的是一段要保存的图案；`Int_EEPROM` 处理控制字节、页边界和写入等待；`Dri_IIC` 处理起始、停止、位传输和 ACK。到了[OLED 工程](../projects/10_OLED/src/course/17-OLED/src/main.c)，底层仍是 P1.6/P1.7 的 I²C，器件接口却换成命令、数据和字模。

协议线脚相同，器件接口仍应分开。排错时先判断问题位于总线时序、器件地址/控制字节，还是应用传入的数据。EEPROM 的数据完整性需要逐字节回读检查，不能只看点阵是否出现图案。

同名底层也可能采用不同实现：[EEPROM 版 `Dri_IIC_SendByte`](../projects/09_I2C与AT24C02/src/course/16-EEPROM/src/Dri/Dri_IIC.c)逐次用掩码取最高位，[OLED 版](../projects/10_OLED/src/course/17-OLED/src/Dri/Dri_IIC.c)使用 `bdata`/`sbit` 取 `msb_bit` 后左移。比较模块时需要检查函数内部和调用环境，不能只按文件名判断版本。

## 综合应用先拆，再合

[DS1302 综合工程](../projects/12_DS1302/src/course/19-DS1302/src/main.c)一次调用 RTC、DS18B20 和 OLED：三线接口读日期，1-Wire 取温度，再通过 I²C 写到屏幕。检查输出时先分清输入数据、格式化和显示传输三个阶段；时钟走时和温度精度还需要独立的对照记录。

[DS18B20 转换后立即读取](../projects/11_DS18B20/src/course/18-DS18B20/src/Int/Int_DS18B20.c)可能返回旧数据；[DS1302 启动时重设示例日期](../projects/12_DS1302/src/course/19-DS1302/src/main.c)会覆盖 RTC 的连续时间。两处行为都保留在原工程中，阅读综合显示结果时需要分别核对。

排查顺序为：**板卡与线脚 → 工程配置与构建产物 → 驱动/接口/应用调用链 → 板端记录。** `pyserial`、HEX 路径和 COM 口变化属于工具链与连接问题，应先于应用逻辑检查。[实际排障入口](常见问题.md)
