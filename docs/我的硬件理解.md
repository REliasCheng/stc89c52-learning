# 我的硬件理解：先沿信号走一遍

[首页](../README.md) · [板级引脚表](../hardware/引脚映射.md) · [学习记录](学习记录.md)

这页是我对**现有课程代码和教学板 V1.0 图纸**的阅读理解，不是示波器测量记录。以后实物结果如果与这里不同，应补证据并改笔记，而不是反过来改写原始源码。

## 数码管：选哪一位，与那一位显示什么

在[静态显示代码](../projects/02_数码管/src/course/03-数码管-静态显示/src/main.c)里，`position <<= 3` 后写入 P1 的相关位，P0 再接收 `codes[6]`。对照[扩展板原理图](../hardware/schematics/extension-board/SCH_51教学扩展板V1.0_2024-05-30.pdf)，我现在用两句话记它：P1.3–P1.5 通过 74HC138 选中一位；P0 决定这位的段码。控制八位显示并不需要给每一位各配一套独立的八根段线。

到[动态显示代码](../projects/02_数码管/src/course/04-数码管-动态显示/src/main.c)，换位前先清 P0，主循环不断刷新缓冲区。我能从代码解释“为什么要扫描”，但还没有在实物上确认位序、消影效果或刷新频率。

## P0 不是只属于 LED

点灯工程直接操作 P0；数码管用 P0 送段码；点阵也借用这组数据线。板上还有 P3.4/P3.5/P3.6 对应的使能。这样看代码时，我不能只看到 `P0 = ...` 就断定是哪一个外设在变化，必须一起检查选通状态。这个习惯也能避免以后把“程序输出错了”和“看错了当前使能的器件”混为一谈。

## 点阵与 I²C：继续沿调用链追

点阵代码把 P1.0/P1.1/P1.2 用来控制 74HC595 的数据、移位时钟和锁存；[静态点阵](../projects/07_点阵/src/course/12-点阵LED/src/main.c)设置图案后，显示刷新仍由 Timer0/接口层维持。这里我还不能凭数组值确定实际图案朝向，需要对照实物。

EEPROM 和 OLED 则共用 P1.6/P1.7。读[EEPROM 工程](../projects/09_I2C与AT24C02/src/course/16-EEPROM/src/main.c)时，我先找 `Int_EEPROM` 再找 `Dri_IIC`；读 OLED 时仍能找到同一组总线线脚。共线不表示两个器件做同一件事，后续要分别查设备地址、读写时序和是否有总线冲突。

下一步需要用实际板卡补：数码管的位序与残影、点阵的方向、I²C 地址/应答。现在没有这些测试数据。
