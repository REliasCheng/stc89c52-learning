# STC89C52RC 嵌入式学习与实验

## 项目简介

围绕 STC89C52RC 教学板，我完成了从 GPIO 输出、显示与输入控制，到中断、定时、串口通信，再到 EEPROM、OLED、温度传感器和实时时钟组合应用的基础实践。仓库保留各阶段的独立工程，也记录我如何从原理图、调用链和故障现象分析软硬件问题。

`src/course/` 保存尚硅谷课程实践的原始工程；主题说明、硬件分析与排障笔记展示我在这些实践中形成的理解。课程代码和个人分析分开标注，[来源说明](THIRD_PARTY_NOTICES.md)可查。

## 技术栈与硬件平台

| 硬件 | 开发与下载 |
| --- | --- |
| STC89C52RC、11.0592 MHz 晶振、51 教学核心板/扩展板 V1.0 | Windows、VS Code + EIDE、Keil C51；STC-ISP 或 EIDE 串口下载 |

实践涉及 C 语言、GPIO、外部中断、Timer0/Timer1、UART、软件 I²C、1-Wire，以及 74HC138 位选、74HC245 段线缓冲、74HC595 点阵驱动、AT24C02、OLED、DS18B20 和 DS1302。器件清单来自现有工程与[板卡资料](hardware/README.md)，不按通用 51 教程推断。引脚也不能凭其他开发板经验套用：P0 复用于 LED、数码管和点阵，P1.6/P1.7 同时连接 EEPROM 与 OLED。[板卡引脚表](hardware/引脚映射.md)

## 学习路线

`GPIO/LED → 数码管 → 按键/蜂鸣器 → 外部中断/定时器 → 点阵 → UART → I²C/AT24C02 → OLED → DS18B20 → DS1302`

这条路线来自已有课程实践：19 个编号工程和一个 `helloworld` 点灯入口按功能归入 12 个主题。不同阶段的驱动版本仍独立保留，便于看出从单文件到 `Com/Dri/Int` 分层的演变。[路线与工程对应表](docs/学习路线.md) · [项目总结](docs/项目总结.md)

## 技术成长记录

- 看数码管时，我先分清「P1 选哪一位」和「P0 送什么段码」，再读动态扫描为什么要持续刷新。[我的硬件理解](docs/我的硬件理解.md)把代码动作与板图接在一起。
- 比较 Timer0 的两个工程后，我开始沿 `main → Dri_Timer0 → 中断/回调` 找行为，而不只盯着 `main.c`。[定时器读码记录](projects/06_定时器/notes/)保留了这个线索。
- 遇到下载问题时，先把 Build、HEX、串口和板上结果分开检查。`serial` 缺失、HEX 路径和 COM 口变化是此前真正遇到的环境问题；处理过程记在[学习记录](docs/学习记录.md)。

这些记录体现了从“看一个端口值”到“沿硬件信号和软件调用链定位问题”的变化。

## 从哪里开始运行

先打开 [LED 点灯工程](projects/01_LED/src/course/00-点亮LED/) 里的 `.uvproj`，用 Keil C51 构建，找到新生成的 HEX，再用 STC 下载工具选**当前**串口下载。后面的 EIDE 工程直接打开各自 `.code-workspace`，配置本机 Keil C51 和 STC 头文件路径，再 Build。串口下载还需要 Python 的 `pyserial`；COM3/COM5 是过去出现过的端口号，不是固定设置。

具体步骤、工程路径和失败时的检查顺序在[编译与烧录](docs/编译与烧录.md)。仓库没有捆绑编译器或安装包，不能只下载 ZIP 就直接得到 HEX。
