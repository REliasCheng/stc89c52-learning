# 外部中断｜从轮询到事件触发

[返回项目模块](../README.md) · [板卡引脚](../../hardware/引脚映射.md) · [课程工程](src/course/09-外部中断/)

## 1. 功能介绍

[09 外部中断工程](src/course/09-外部中断/)让 P3.2 上的按键触发 INT0，由中断服务函数切换 P0.0 LED。与上一阶段在主循环轮询 P3.2 不同，这里输入事件有了独立入口，main 的无限循环本身不执行按键判断。

## 2. 硬件连接分析

STC89C52RC P3.2 兼作普通输入和 INT0 外部中断输入；开发板按键把该线拉到有效低电平。输出仍是 P0.0 → LED，并受板上 P3.4 LED 使能约束。硬件连接没有因软件改用中断而改变，变化的是 MCU 如何响应 P3.2 上的下降沿。

## 3. 软件实现

main 调用 INT0_Init，随后空转。初始化打开全局中断 EA、INT0 允许位 EX0，并把 IT0 设为下降沿触发。发生中断后，interrupt 0 服务函数调用公共延时函数做约 10 ms 消抖，再确认按键电平并反转 LED。这里的主要路径是“引脚下降沿 → 中断控制器 → ISR → P0 输出”，没有必要把空 main 解读为缺少功能。

## 4. 核心代码分析

- **EA / EX0**：分别打开全局与 INT0 的响应入口；只配置一个而漏另一个，ISR 都不会按预期进入。
- **IT0**：决定触发方式，本工程按下降沿进入。
- **ISR 内复核 P3.2**：下降沿后再确认输入仍有效，配合延时抑制机械抖动。
- **P00 取反**：一次确认事件对应一次 LED 状态切换。

## 5. 技术难点

中断提高了事件响应的组织清晰度，但 ISR 中执行 10 ms 软件等待会占用中断处理时间。后续若与串口或计时并用，需要重新评估优先级和中断执行时长。这个工程让我把“功能能工作”和“中断处理是否适合扩展”分成两个层面来分析。

## 6. 调试记录

若按键无响应，先核 P3.2 电平和板上接线，再看 EA、EX0、IT0 与 ISR 的 interrupt 0 声明；若重复触发，再检查机械抖动与 ISR 的复核路径。与独立按键工程对比时，特别注意两者都使用 P3.2，却采用不同的软件入口。[读码笔记](notes/)保留这种对照及 ISR 时间占用分析。
