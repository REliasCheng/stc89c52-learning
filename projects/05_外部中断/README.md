# 05 · 外部中断：按键不用只靠轮询

[实验目录](../README.md) · [INT0 引脚](../../hardware/引脚映射.md)

[课程工程](src/course/09-外部中断/)把 P3.2 用作 INT0：`INT0_Init()` 打开全局中断和 EX0，设置下降沿触发；主循环为空，按键事件落在 `interrupt 0` 处理函数里。它与上一章 P3.2 作为普通按键的用法形成了直接对照。

## 从轮询走向事件入口

同一 P3.2 在独立按键工程里作为普通输入，这里接到 STC89C52RC 的 INT0。`INT0_Init()` 依次设置 `EA`、`EX0` 和下降沿触发 `IT0`；`main()` 空转，`interrupt 0` 才在按键沿到来时处理 P0.0 LED。主循环没有动作不等于程序没有响应，这是我读中断工程时建立的第一条判断。

原 ISR 先调用 `Com_Util_Delay1ms(10)`，再确认 P3.2 仍为低并翻转 LED。这样把消抖写得直观，却让 CPU 在中断里等待；若以后还有计时或通信中断，就需要评估占用时间。[笔记](notes/)保留这个原始取舍，没有改成“标准实现”。成果是可独立打开的课程工程及轮询/中断对照分析；仓库没有按键抖动次数的原始测试数据。
