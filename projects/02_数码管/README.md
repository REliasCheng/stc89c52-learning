# 02 · 数码管：段码与位选是两回事

[实验目录](../README.md) · [引脚表](../../hardware/引脚映射.md)

这组三步最值得连着看：[静态显示](src/course/03-数码管-静态显示/)、[动态扫描](src/course/04-数码管-动态显示/)、[模块化版本](src/course/05-数码管-模块化编程/)。静态例子里 `P1.3–P1.5` 经 74HC138 选中某一位，`P0` 经 74HC245 缓冲后送共阴数码管段码；动态例子把每位段码放到缓冲区，不断刷新；最后一个把接口移进 `Int_DigitalTube`。

`04` 的 `u16` 在原文件中实际定义为 `unsigned char`，与名称不符。这里保留原样，不能把本组当成已经修复过的驱动。[读码笔记](notes/)记录了这一点及消影顺序。

## 信号怎么走，代码怎么变

`STC89C52RC P1.3–P1.5 → 74HC138 → 数码管位选`；`P0 → 段线`，P3.6 控制数码管使能。静态工程的 `position <<= 3` 是把 0–7 的位号移到 P1.3–P1.5，`P1 &= 0xC7` 先清这三位，再写新位号；P0 随后输出段码。动态工程增加八字节显示缓冲，每次换位先清 P0，再轮流送出段码。模块化工程把这套动作收进 `Int_DigitalTube`，`main()` 只负责设置数字和持续刷新。

我现在把“选哪一位”和“这一位显示什么”当成两个独立问题。这样分析乱码、错位或残影时，能分别检查 P1 译码、P0 段码和刷新循环，而不是只改数字数组。`04` 的 `u16` 实际被定义成 `unsigned char`，延时参数有截断风险；这是原代码的事实，[笔记](notes/)保留了对照。三份课程工程完整留存；`03` 用旧版 `.eide/eide.yml`，后两份用 `.eide/eide.json`。[环境说明](../../docs/开发环境.md)列了打开方式。仓库不虚构显示亮度或位序的测量值。
