# 定时器｜Timer0 时间基准与回调封装

[返回项目模块](../README.md) · [工程结构](../../docs/工程结构.md) · [工程源码](src/course/)

[10 定时器](src/course/10-定时器/)在 Timer0 ISR 中计数并控制 LED；[11 定时器封装](src/course/11-定时器封装/)改由应用注册 `LED_Blink` 回调。两个版本完成从“中断里直接写业务”到“时间基准调用应用函数”的接口拆分，后续点阵与 UART 工程复用了回调方式。

## Timer 与输出

Timer0 是 STC89C52RC 内部资源，不需要额外时钟线接到扩展板。板上 11.0592 MHz 晶振为 MCU 提供时钟；本工程按 12T 工作方式计算 Timer0 重装值。输出结果通过 P0.0 → LED（P3.4 使能）观察。定时中断与 LED 电路是两条不同路径：前者决定何时执行，后者决定执行后哪个外设变化。

## 两个实现

10 工程：main → Dri_Timer0 初始化 → Timer0 interrupt 1 → count 累积 → LED 翻转。11 工程：main 初始化 Timer0，并用 Dri_Timer0_RegisterCallback(LED_Blink) 注册任务；ISR 到来时由驱动遍历回调槽并调用应用函数。Com_Util 提供公共延时等工具，但不是定时中断的入口。两个 Dri_Timer0 版本各自在原工程中保留，不合并成“最新版”。

### 重装与回调

- **TH0/TL0=64614 的重装**：模式 1 定时器在每次溢出后重新装入起点；按 11.0592 MHz 与 12T 可推导约 1 ms 的中断基准。
- **count 达到 500 后切换 LED**：10 工程在 ISR 内直接完成应用动作，是最短调用链。
- **RegisterCallback(LED_Blink)**：11 工程把应用行为作为函数指针交给驱动，驱动维护最多四个回调槽；扩展任务不必把每一种外设动作硬写进定时器 ISR。
- 10 工程 ISR 标识里的 Dir 与其他文件的 Dri 命名不一致，阅读和查找时要按原文件名定位。

## 调度约束

定时器给出相对稳定的节拍，但中断处理时间、注册回调数量和任务自身耗时都会影响扩展性。这里最有价值的工程变化，是把“何时执行”与“执行什么”分开。点阵刷新需要快节拍，UART 空闲判断也能接入同一类回调；主循环因此不必依赖长延时承担所有时间控制。

## 定时器检查

LED 不按预期变化时，先核对 EA/ET0/TR0、工作模式和重装值，再确认 `interrupt 1` 是否进入，最后检查 `count`、注册位置和回调槽。[读码笔记](notes/)对比两个版本；周期说明按寄存器配置推导，板端波形可按调试步骤测量。
