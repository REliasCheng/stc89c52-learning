# DS1302｜RTC、温度与 OLED 组合应用

[返回项目模块](../README.md) · [板卡引脚](../../hardware/引脚映射.md) · [工程源码](src/course/19-DS1302/)

[19 DS1302 工程](src/course/19-DS1302/)把实时时钟、温度传感器和 OLED 接入同一应用：启动时写入示例日期，循环读取时间与温度，格式化后在屏幕上输出。该工程形成 RTC、传感器和显示器的完整调用链。

## RTC 连接

RTC：STC89C52RC P3.7/SCLK → DS1302 时钟，P4.0/IO ↔ 双向数据，P4.1/CE → 片选；RTC 旁有 32.768 kHz 晶振。温度：P4.4 ↔ DS18B20 的 1-Wire 数据线。显示：P1.6/P1.7 → OLED 软件 I²C。三组外设走不同接口，主控在应用层汇合数据，不是把三种器件接在同一通信总线上。

## 读取与显示

main 依次初始化显示与 RTC，调用 Int_DS1302_SetDate 写入示例值；循环中通过 Int_DS1302 获取日期时间、通过 Int_DS18B20 获取温度，再用 sprintf 组织两行文本，交给 Int_OLED 输出。RTC 接口负责 DS1302 的三线读写和 BCD/十进制转换；传感器和显示各走自己的 Int/Dri 路径。这里的 main 是设备协作与信息排版的应用层。

### 三线传输与 BCD

- **DS1302 三线读写**：CE 有效后按低位先行发送命令和数据，不能直接套 UART 或 I²C 的位序。
- **BCD 转换**：日期时间寄存器使用 BCD 表示，读写接口在 BCD 与普通十进制数字之间转换，main 才能直接用于文本格式化。
- **SetDate 的调用位置**：每次启动都会写入固定示例日期；因此当前工程演示“写入并显示”，而不是断电持续计时的完整钟表。
- **WEEK_NAME[day_of_week-1]**：依赖星期值在 1–7 范围内；若寄存器数据异常，该索引需要防护。温度读取还沿用上一模块的转换顺序。

## 启动时间处理

一个屏幕上的两行结果依赖 RTC 三线时序、BCD 转换、1-Wire 采样、I²C 显示与格式化代码。设备驱动负责取得数据，main 负责组织内容和输出。

## RTC 检查

若时间异常，先检查 CE/SCLK/IO、读写位序和 BCD 转换，再看初始化是否每次覆盖 RTC；若温度异常，转查 P4.4 和 DS18B20 的转换时序；若两行均不显示，优先排查 OLED 的 I²C 与初始化。[组合调用笔记](notes/)保留这些边界。持续走时或后备电源效果需要实物记录后才能补充。
