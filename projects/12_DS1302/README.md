# 12 · DS1302：把时间和温度放到同一屏

[实验目录](../README.md) · [硬件引脚](../../hardware/引脚映射.md)

[19-DS1302 示例](src/course/19-DS1302/)把 RTC、DS18B20 和 OLED 组合起来：初始化时给 DS1302 写一组示例日期，主循环读回日期时间、读温度，再用 `sprintf` 输出两行文字。DS1302 用 P3.7/P4.0/P4.1，温度仍用 P4.4，OLED 仍走 P1.6/P1.7。

## 从单器件驱动走到组合应用

DS1302 走 `P3.7 SCLK / P4.0 IO / P4.1 CE` 三线接口；DS18B20 仍走 P4.4，OLED 走 P1.6/P1.7。`Int_DS1302` 按低位先发的时序写命令和数据，将日期时间转换为 BCD 写入，再读出转回十进制。`main()` 初始化 OLED、设置示例日期，循环中取 RTC 与温度，把两者格式化到屏幕两行。调用链跨 `Int_DS1302`、`Int_DS18B20`、`Int_OLED` 与各自底层，体现了从单外设练习到应用层组合。

我的分析方法是先检查各接口的独立结果，再看 `sprintf` 和显示布局；屏幕上一处异常可能来自时间寄存器、温度读取或显示传输。原程序每次启动都调用 `SetDate`，所以它展示的是“设置并显示示例时间”，不能冒充断电保持的成品时钟。`WEEK_NAME[day_of_week - 1]` 依赖 1–7 的范围，温度路径还继承上一章的转换等待疑点。[笔记](notes/)保留这些边界；没有走时或电池保持的测量记录就不补造。
