# 蜂鸣器｜输入、声音与显示联动

[返回项目模块](../README.md) · [板卡引脚](../../hardware/引脚映射.md) · [课程工程](src/course/08-蜂鸣器/)

## 1. 功能介绍

[08 蜂鸣器工程](src/course/08-蜂鸣器/)把矩阵按键、蜂鸣器和数码管放在一个主循环：取得键号后输出声音反馈，并显示键值。这是从单一外设控制走向多输出联动的过渡工程。

## 2. 硬件连接分析

输入：P2.0–P2.3 行驱动与 P2.4–P2.7 列输入组成矩阵键。声音：STC89C52RC P4.6 → 三极管驱动级 → 蜂鸣器，IO 只提供控制信号，不直接承担蜂鸣器负载。显示：P1.3–P1.5 经 74HC138 选位，P0 经 74HC245 送段码，P3.6 控制使能。这三条路径共享 CPU 时间，但各有独立的电气连接。

## 3. 软件实现

main 轮询 Int_KeyMatrix，得到键号后调用 Int_Buzzer_Buzz，再调用 Int_DigitalTube 设置显示值；主循环还持续刷新数码管。蜂鸣器接口负责 P4.6 的翻转节奏，矩阵接口负责扫描，显示接口负责段码与位选，应用层完成联动。

## 4. 核心代码分析

Int_Buzzer_Buzz() 循环 100 次，每轮翻转 P4.6 并延时约 1 ms。周期性电平变化驱动发声；发声函数返回后，main 才继续更新和刷新显示。这种写法容易读，但也意味着发声期间应用主循环被占用。蜂鸣器是否持续响、数码管是否及时刷新，需要分别沿 P4.6 输出与主循环时间线分析。

## 5. 技术难点

难点是多外设争用执行时间，而不是多接一根蜂鸣器线。显示需要反复扫描，阻塞式声音输出却暂时占住主循环。本实验提供了一个清楚的改进方向：以后若转向定时器调度，可把声音翻转与显示刷新拆为独立节拍；当前版本保留原有实现。

## 6. 调试记录

遇到按键有反应但没有声音，可依次检查矩阵键返回值、Int_Buzzer_Buzz 是否被调用、P4.6 与三极管驱动通路；若显示闪烁，先检查阻塞调用发生的时间段，再看段码和位选。[观察笔记](notes/)区分这两条排查线，实物演示中可补充声音与显示的同步录像。
