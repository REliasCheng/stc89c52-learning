# 11 · DS18B20：温度转换不是“发完命令立刻读”

[实验目录](../README.md) · [引脚](../../hardware/引脚映射.md)

[18-DS18B20 示例](src/course/18-DS18B20/)把 P4.4 上的 1-Wire 温度读数显示到 OLED，主循环约每 500 ms 更新一次。调用链是 `main → Int_DS18B20 → Dri_1Wire`，显示走另一条 `Int_OLED → Dri_IIC`，比较适合练习跨接口追代码。

## 传感器时序与显示分开看

`P4.4 DQ → DS18B20 1-Wire`，[扩展板图第 10 页](../../hardware/schematics/extension-board/SCH_51教学扩展板V1.0_2024-05-30.pdf)给数据线配了 10 kΩ 上拉；显示端仍由 `P1.6/P1.7 → OLED` 承担。`Dri_1Wire` 实现复位、读写时隙；`Int_DS18B20_GetTemperature()` 发 `0xCC` 跳过 ROM、`0x44` 启动转换，再发 `0xBE` 读暂存器低/高字节。`main()` 把返回值送给 `Int_OLED_ShowNum`，循环末尾延时 500 ms。一路是传感器获取，一路是屏幕输出，故障不能只凭显示数字定位。

我在这个工程里特别关注“时序上看似有延时”和“本次转换确实完成”的区别：原函数在 `0x44` 后立即重新复位读取，`main()` 的 500 ms 在读取**之后**。这是可从源码确认的风险，不是杜撰的错误温度现象。[笔记](notes/)保留命令顺序与手册入口；课程源码原样保留，仓库不宣称已测出温度精度。
