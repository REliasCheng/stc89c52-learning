# DS18B20｜1-Wire 时序与温度显示

[返回项目模块](../README.md) · [板卡引脚](../../hardware/引脚映射.md) · [课程工程](src/course/18-DS18B20/)

## 1. 功能介绍

[18 DS18B20 工程](src/course/18-DS18B20/)通过 1-Wire 读取温度，并把结果交给 OLED 显示。一个应用流程同时使用 1-Wire 传感器与 I²C 屏幕，便于从接口层追踪“采集—转换—显示”的数据路径。

## 2. 硬件连接分析

STC89C52RC P4.4/DQ ↔ DS18B20 单线数据端，扩展板在 DQ 上配置 10 kΩ 上拉；数据脚需要在 MCU 输出与读取之间切换。显示走另一条路径：P1.6/P1.7 → OLED。两类外设使用不同引脚和协议，因此屏幕显示异常不必然等于温度读取异常，反之亦然。

## 3. 软件实现

main 初始化 OLED，在循环中调用 Int_DS18B20_GetTemperature，再调用 Int_OLED_ShowNum，随后约延时 500 ms。温度接口内部经 Dri_1Wire 完成复位、写字节和读字节；显示接口经 Dri_IIC 发往 OLED。函数链清楚地区分了传感器底层时序、器件命令和最终文本呈现。

## 4. 核心代码分析

- **Dri_1Wire_Reset/ReadByte/WriteByte**：把微秒级复位和读写时隙封装起来；上层不直接在 main 中拼时序。
- **0xCC → 0x44**：跳过 ROM 选择并启动温度转换；之后再次复位，发 0xCC → 0xBE 读取暂存器低/高字节。
- **高低字节合成与移位**：接口将原始温度数据换算成供 OLED 显示的整数值；读代码时要同时看符号与精度处理。
- 当前源码在 0x44 后立即启动下一次读取流程；main 的 500 ms 延时发生在本次读数之后。这是分析温度数据新鲜度时必须考虑的顺序。

## 5. 技术难点

1-Wire 的复位/存在脉冲与读写时隙对时间敏感，不能只看命令字节；温度转换本身还需要完成时间。本模块展示了接口封装与跨总线组合，也暴露了时序顺序对结果含义的影响。课程版本保持原逻辑，后续若改成非阻塞转换，应另建个人版本并记录验证。

## 6. 调试记录

屏幕数字异常时，先区分 OLED 显示链与 P4.4 传感器链，再看上拉、复位响应、命令顺序和转换等待。对固定或滞后的数值，优先回看 0x44 后到 0xBE 前的时间，而不是先改显示格式。[时序笔记](notes/)对应源码与手册入口。这里不填写未经记录的温度精度或对照测量。
