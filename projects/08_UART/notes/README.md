# UART 读码与待测项

- [14 的 `main.c`](../src/course/14-串口-单字节命令/src/main.c)：收 `A` 设 `P0=0x00` 并回 `Ok: LED is on`；收 `B` 设 `P0=0xFF`。驱动以非零 `s_buffer` 代表收到字节，所以 `0x00` 无法作为普通有效命令。
- [15 的 `main.c`](../src/course/15-串口-多字节命令/src/main.c)：比较 `on` / `off`。接收数组是 16 字节，驱动 ISR 对写入 `s_buffer[s_index++]` 没有上界判断，不能直接用长串口输入当稳定性测试。
- 串口还依赖本机 CH340K 的当前 COM 口、同一个 Python 环境里的 `pyserial`，以及本次构建的 HEX。此前碰到过这些环境问题；处理顺序在[编译与烧录](../../../docs/编译与烧录.md)。

待实测：波特率、命令回显/回复、连续收包、满缓冲与断电后再次下载。边界问题修订应单独提交并附原版对照。

此前的 `serial`、HEX 路径和 COM 口问题发生在**构建/上传链路**，不能算作“UART 应用代码收包已经测过”。现在排查时我会先确认本次 Build 和 HEX，再确认当前端口与 Python，最后才判断 `Dri_UART` 的 RI/TI 处理是否有问题；这样不会把环境故障误写成程序 Bug。
