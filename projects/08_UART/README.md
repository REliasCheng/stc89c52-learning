# 08 · UART：命令能收到，边界也要守住

[实验目录](../README.md) · [实际排障](../../docs/学习记录.md)

[单字节版本](src/course/14-串口-单字节命令/)识别 `A`/`B` 来开关 LED；[多字节版本](src/course/15-串口-多字节命令/)识别 `on`/`off`，用 Timer0 回调根据空闲时间判断一条命令收完。两个版本都通过 Timer1 产生串口波特率，用 UART 中断收发。

## 从字节到命令帧

硬件通路是 STC89C52RC 的 P3.0/RXD、P3.1/TXD 经板上串口链路与电脑通信。`Dri_UART_Init()` 将串口设为模式 1，Timer1 自动重装值 `253` 产生波特率；`interrupt 4` 分别处理 RI 收到的数据和 TI 发送完成。14 工程把 `A/B` 直接变成 P0 LED 的开关命令；15 工程多了 16 字节缓冲，Timer0 回调统计约 10 个空闲节拍后才把字符串交给 `main()` 比较 `on/off`。

我的分析重点从“能收一个字符”推进到“什么时候算完整命令，以及边界在哪里”。14 工程用非零 `s_buffer` 当接收标志，`0x00` 无法正常表示；它还启用了 `ET1` 却未见 Timer1 ISR。15 工程的 `s_buffer[s_index++]` 没有长度保护，主程序字符串还需终止符空间。[笔记](notes/)保留原版风险，不宣称已修复。实际遇到的 `serial`、HEX 路径和 COM 口问题属于下载链路；排查必须先把环境故障与 UART 应用逻辑分开。[排障记录](../../docs/学习记录.md)
