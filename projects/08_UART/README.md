# UART｜从字节命令到缓冲式接收

[返回项目模块](../README.md) · [串口引脚](../../hardware/引脚映射.md) · [工程源码](src/course/)

[14 单字节命令](src/course/14-串口-单字节命令/)用 A/B 控制 LED；[15 多字节命令](src/course/15-串口-多字节命令/)用 on/off 指令，并利用接收空闲时间判断命令结束。两个版本分别回答“如何收一个字节”和“如何在连续字节中划出一条命令”。

## 串口通路

STC89C52RC P3.0/RXD 接收、P3.1/TXD 发送，经核心板 CH340K 转为 PC 串口链路；P0 LED 是命令执行后的输出。接线与应用协议应分开排查：PC 看不到板卡串口，先查 USB/CH340K/COM；能收字节却不执行命令，再查波特率、缓冲和比较逻辑。板上 11.0592 MHz 时钟也参与 Timer1 波特率产生。

## 接收与命令流程

两版均由 main 调用 Dri_UART_Init，串口模式 1 的接收与发送完成落在 interrupt 4：RI 分支取入 SBUF，TI 分支处理发送结束。Timer1 自动重装为串口提供波特率。14 工程把单字节直接变为 P0 LED 动作；15 工程另用 Timer0 回调累积接收空闲节拍，约 10 个节拍后让 main 对 s_buffer 中的 on/off 文本作命令比较。

### 寄存器与缓冲区

- **Timer1 重装值 253**：与模式 1 的波特率设置配合，不能只改 PC 端串口参数而不核工程配置。
- **RI/TI 分开处理**：同一个串口中断入口包含接收与发送完成两类事件。
- **14 工程的 s_buffer**：使用非零值表达“收到数据”，因此字节 0x00 不能作为普通命令数据；该版还打开 ET1，但工程中没有相应 Timer1 ISR。
- **15 工程的 s_buffer[16] 与 s_index++**：用缓冲累计多字节命令，但源码没有长度上界检查；字符串比较还依赖终止符。两个版本的边界不同，必须独立阅读。

## 帧边界

单字节命令不需要成帧，多字节命令必须确定结束点。15 工程用时间间隔作分帧依据，并把中断接收、缓冲组织和主循环命令处理分开；源码仍需检查缓存容量和异常输入。

## 串口检查

环境排障涉及 Python 缺少 `serial`、pyserial 安装到错误解释器、HEX 输出路径以及 CH340K 的 COM3/COM5 变化，详见[维护记录](../../docs/学习记录.md)。复现 UART 时先确认端口和本次 HEX，再核对两端波特率与数据格式；收到内容但指令不生效时，再检查 RI、缓存结束条件和 `on/off` 比较。[接口笔记](notes/)记录 0x00 与缓冲区边界问题。
