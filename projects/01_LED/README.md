# LED｜从单引脚到整组端口

[返回项目模块](../README.md) · [板卡引脚](../../hardware/引脚映射.md) · [课程工程](src/course/)

这一组由三个可独立构建的 Keil 工程组成：[00 点亮 LED](src/course/00-点亮LED/)、[01 LED 闪烁](src/course/01-LED-闪烁/)、[02 LED 流水](src/course/02-LED-流水/)。控制范围依次从 P0.0 扩展到整个 P0 端口，建立“端口电平—板上连接—外设状态”的基础对应关系。早期工程没有 Int/Dri 分层，直接在 main.c 操作端口。

## 信号路径

信号路径：STC89C52RC 的 P0.0–P0.7 → 扩展板 LED 数据线；P3.4 → LED 使能。板图中的 LED 为低电平有效，因此给 P0 某位输出 0 才点亮相应灯。P0 后续也接数码管和点阵，P3.4 的使能让同一组数据线可以服务不同外设。读 LED 代码时，端口值与使能状态要一起看。

## 三个工程

00 工程的 main.c 直接令 P00=0。01 工程在循环中取反 P00，再进行软件延时；02 工程用 tmp 维护移动的位图，取反后写整组 P0。三个工程都以 main 为应用入口，不存在需要硬凑出的 Int 层调用。各工程的 .uvproj 与源码同层，按原路径即可打开。

### 关键代码

- **P00=0**：用最小输出动作验证 P0.0 与 LED 的低有效关系。
- **P00=~P00**：每次循环反转端口状态；可见的闪烁节奏由后面的延时决定。
- **P0=~tmp**：tmp 表达“当前亮灯位置”，取反则把该位图映射到低有效 LED。左移推进亮灯位置，到边界再从头开始。这比逐个给八个引脚写条件更容易维护。

## 时序与共享端口

软件延时与 11.0592 MHz 时钟有关，不能把函数名直接当作精确时间。P0 整口赋值会同时改变所有共享输出位，后续实验因此需要同时管理数据口和外设使能。

## 上板检查

实际使用过的构建/烧录排查链是：确认本次 Keil 构建产生 HEX → 核对下载工具所选串口 → 再检查 P3.4 使能与 P0 极性。若 HEX 没更新，板上仍是旧程序，改端口值不会改变现象。[编译与烧录](../../docs/编译与烧录.md)记录了路径检查方法。LED 专属的亮度、时长数值没有历史记录，本节不填入推测值。
