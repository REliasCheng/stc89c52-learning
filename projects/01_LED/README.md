# 01 · LED：先让程序在板上跑起来

[实验目录](../README.md) · [接线](../../hardware/引脚映射.md)

这组保留了三个逐步增加难度的课程工程：[点亮 LED](src/course/00-点亮LED/)、[闪烁](src/course/01-LED-闪烁/)和[流水](src/course/02-LED-流水/)。它们还是 Keil 的平铺结构，`.uvproj` 与 `main.c` 在同一级；我没有为了目录整齐把源码移走，避免工程相对路径失效。

最小例子只把 `P00` 拉低；闪烁例子取反同一个端口；流水例子用 `P0 = ~tmp` 和左移逐颗改变 LED。P0 接 LED，P3.4 是扩展板上的 LED 使能，亮灭极性要结合原理图看。[这里记了读代码时的细节](notes/)。

## 我从三份工程里抓住的主线

`STC89C52RC → P0.0～P0.7 → 扩展板 LED`，同时还要看 P3.4 的 LED 使能。最小工程的 `P00 = 0` 是端口输出与低电平点亮的起点；闪烁工程用 `P00 = ~P00` 和标注 11.0592 MHz 的软件延时；流水工程把 `tmp` 左移，写 `P0 = ~tmp`。取反不是装饰，它对应这套板的亮灭极性。从[最小点灯](src/course/00-点亮LED/main.c)到[流水灯](src/course/02-LED-流水/main.c)，控制对象从单脚扩展到整组端口。

这组实践让我建立了最基本的排查顺序：程序有没有构建成**本次** HEX，P0 的输出值与 LED 极性是否相符，P3.4 是否选通 LED。延时节奏还受晶振和执行周期影响，不能只拿源码里的函数名当精确测量。仓库保留了三份可独立打开的 Keil 工程与[读码记录](notes/)；没有留存的亮灯照片或时长数据不补写。入口是 `00-点亮LED/helloworld.uvproj`，[编译与烧录](../../docs/编译与烧录.md)说明了工具链步骤。
