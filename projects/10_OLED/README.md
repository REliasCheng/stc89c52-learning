# OLED｜总线通信与显示接口封装

[返回项目模块](../README.md) · [板卡引脚](../../hardware/引脚映射.md) · [课程工程](src/course/17-OLED/)

## 1. 功能介绍

[17 OLED 工程](src/course/17-OLED/)初始化并清屏，在屏幕上输出 Hello World! 和 -12345678。应用只提交文本和数字，Int_OLED 负责命令、地址与字模，Dri_IIC 负责 P1.6/P1.7 上的总线动作。这是“器件显示接口建在通信驱动之上”的直接例子。

## 2. 硬件连接分析

STC89C52RC P1.6/SDA、P1.7/SCL → OLED 的 I²C 接口；与 AT24C02 共用总线。通过器件控制字节区分设备，不能因为两者共线就交替使用同一套地址。屏幕的供电和地由扩展板提供，软件层还必须正确发送初始化命令与显示数据。此工程使用的写控制字节为 0x78；具体屏幕控制器型号仍以实际模块标识和随附资料核对。

## 3. 软件实现

main → Int_OLED_Init → Int_OLED_Clear → Int_OLED_ShowStr/ShowNum；Int_OLED 的命令和数据发送最终都调用 Dri_IIC。ShowNum 先把整数格式化为字符，再复用字符串显示路径。main 不直接逐位翻转 SDA/SCL，也不逐字节组织字模行，这些细节由接口层承担。

## 4. 核心代码分析

- **0x78 + 0x00/0x40**：先发送该屏的写控制字节，再用控制字段区别命令和图像数据。黑屏时这两类字节的顺序值得先核对。
- **Int_OLED_Clear()**：遍历显示页和列，写入清零数据；它不只是覆盖当前两个字符串位置。
- **Int_OLED_ShowStr()**：按字库取字符图形，并分上下部分写入页面；字符位置、列地址与字模顺序共同决定排版。
- **Int_OLED_ShowNum()**：把数字转为文本交给 ShowStr，因此显示负数也沿同一条字符串路径。

## 5. 技术难点

显示失败可能出在供电、I²C 电平、设备地址、初始化顺序、页/列定位或字模；“main 里写了字符串”并不意味着数据到了屏幕。这个模块体现了将总线驱动、器件命令和应用内容逐层分开的价值，也让我能按层排查，而不是随意修改字模数组。

## 6. 调试记录

复现时按“供电与 P1.6/P1.7 → 总线应答/控制字节 → 初始化命令 → 页面地址 → 字模内容”定位。若 AT24C02 正常而 OLED 不显示，可先比较地址和命令数据区分；若两者都不通，优先查共享总线。[读码笔记](notes/)列出调用点。实拍显示效果将与工程截图一起补入，不以源码字符串充当照片。
